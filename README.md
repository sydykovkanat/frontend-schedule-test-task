# Расписание секций

Интерфейс для распределения учебных секций по недельной сетке. Основной способ работы — Drag & Drop: секция перетаскивается из списка в свободный слот, занятие переносится между слотами или возвращается в нераспределённые.

## Запуск

```bash
npm install
npm run dev
```

Приложение поднимется на `http://localhost:5173`.

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Дев-сервер |
| `npm run build` | Проверка типов и продакшен-сборка |
| `npm run preview` | Просмотр собранной версии |
| `npm test` | Тесты |
| `npm run test:coverage` | Тесты с отчётом о покрытии |
| `npm run typecheck` | Только проверка типов |

Чтобы посмотреть состояние ошибки загрузки, откройте `http://localhost:5173/?fail=1`.

## Архитектура

Слои разделены так, чтобы бизнес-логику можно было читать и тестировать без React.

```
src/
├── domain/      правила, подбор, прогресс, фильтрация — чистые функции
├── data/        mock API, схема данных
├── state/       редьюсер, история, сохранение
├── features/    drag&drop, список секций, сетка, редактор, панель
├── components/ui/       примитивы shadcn (base-nova, на Base UI)
├── components/schedule/ элементы, специфичные для расписания
└── lib/         вспомогательные утилиты
```

### Правила конфликтов

Ключевое требование задания — проверки не зашиты в обработчики JSX. Каждое правило это функция `(target, scope, context) => Conflict | null`, все они собраны в один список в `domain/conflicts.ts`:

```ts
const RULES: readonly ConflictRule[] = [
  sectionAlreadyInSlot,
  teacherUnavailable,
  teacherAlreadyTeaching,
  roomAlreadyTaken,
  roomTooSmall,
  roomTypeMismatch,
  weeklyQuotaReached,
]
```

Добавить правило — значит дописать функцию в список. Компоненты получают уже готовый результат и не знают, из чего он собран.

### Две степени строгости

Конфликты делятся на `error` (drop запрещён) и `warning` (drop разрешён, но с пометкой). Это не украшательство, а следствие данных: в наборе одна компьютерная лаборатория на 18 мест, а секций с `preferredRoomType: COMPUTER_LAB` четыре, причём в `CS101-01` учится 24 человека. Если сделать несовпадение типа аудитории блокирующим, эта секция не встанет никуда — у неё не будет ни одного допустимого слота за всю неделю. Поэтому блокируют только пять правил из задания плюс невозможность подобрать преподавателя или аудиторию, а тип аудитории и перебор недельной нормы предупреждают.

### Подбор преподавателя и аудитории

`domain/assignment.ts` закрывает занятие до того, как сработают правила:

- преподаватель берётся у секции; если он не назначен — выбирается первый свободный из `allowedTeacherIds`, и занятие помечается как подобранное автоматически;
- аудитория выбирается сначала нужного типа, а внутри типа — самая тесная из вмещающих, чтобы большие аудитории оставались свободными для больших секций.

Если преподаватель был подобран автоматически, после drop сразу открывается компактный редактор — подтвердить или сменить выбор.

### Состояние

`state/scheduleReducer.ts` — обычный редьюсер без мутаций: любое действие возвращает новый объект, а действие с неизвестным `lessonId` возвращает то же самое состояние по ссылке. Благодаря этому его можно обернуть в `state/history.ts` — универсальную историю `{ past, present, future }` с ограничением глубины. Undo/Redo работают на `Ctrl+Z` и `Ctrl+Shift+Z`.

Занятия сохраняются в `localStorage` и при чтении проходят ту же zod-схему, что и mock-файл, поэтому устаревшая или испорченная запись просто игнорируется.

### Drag & Drop

Используется `@dnd-kit/core`. При старте перетаскивания один раз считается расклад всей недели — 30 ячеек через `evaluateWeek`, — и дальше ячейки только читают готовый результат:

- зелёная — ставить можно;
- жёлтая — можно, но есть оговорка;
- красная с перечёркиванием — нельзя, причина видна в превью под курсором и в строке состояния.

До завершения drop в целевой ячейке рисуется призрак будущего занятия с подобранными преподавателем и аудиторией.

Тот же расклад показывается по клику на секцию — без перетаскивания, чтобы можно было просто посмотреть, куда она вообще помещается.

### Интерфейс

Интерфейс собран на примитивах shadcn — пресет `base-nova` поверх Base UI: `Button`, `Input`, `Select`, `Dialog`, `Label`, `Separator`, `Tooltip`, `Alert`, `Skeleton`, `Kbd`, `Empty`. Добавить новый — `npx shadcn@latest add <имя>`.

Своих компонентов ровно два, и оба не примитивы, а способ показать данные: `ProgressPips` рисует прогресс секции делениями по числу нужных занятий, `ConflictList` выводит конфликты с разделением на ошибки и предупреждения.

Список секций прокручивается обычным `div`, а не `ScrollArea`: виртуализации нужен прямой доступ к элементу со скроллом, а `ScrollArea` держит его внутри себя.

## Работа с большим количеством секций

- поиск по коду, предмету и преподавателю;
- фильтры по преподавателю, аудитории и статусу распределения;
- прогресс каждой секции показан делениями, которых ровно столько, сколько занятий нужно в неделю — «осталось одно» читается без чтения цифр;
- список виртуализирован (`lib/useListWindow.ts`): в DOM живут только видимые строки, поэтому несколько сотен секций не тормозят прокрутку.

## Доступность

Drag & Drop полностью повторяется с клавиатуры: `Tab` до карточки, `Пробел` — взять, стрелки — переход между слотами сетки, `Пробел` — поставить, `Esc` — отмена. Стрелочная навигация написана под сетку (`features/dnd/gridCoordinateGetter.ts`), а не сдвигает элемент на фиксированное число пикселей. Каждый переход озвучивается вместе с вердиктом: «Четверг, 16:00. Нельзя: М. Садыков — недоступен».

Запрещённые ячейки помечены не только цветом, но и диагональным перечёркиванием.

## Тесты

```bash
npm test
```

127 тестов, покрытие 83% по проекту и 98% по доменному слою.

Тесты работают на настоящем `schedule-mock-data.json`, а не на выдуманных данных, поэтому заодно стерегут допущения о самом наборе. Например, расклад недели для `CS101-01` зафиксирован как 0 свободных слотов, 26 с оговоркой и 4 закрытых — если правила поедут, это сразу упадёт.

Проверяются четыре уровня:

- правила, подбор, прогресс и фильтрация — на чистых функциях;
- редьюсер, история и сохранение — на состоянии;
- клавиатурная навигация по сетке и виртуализация списка — на отдельных модулях;
- рабочий экран целиком (`src/Workbench.test.tsx`) — поиск, фильтры, подсветка расклада, редактор занятия, удаление, копирование, undo/redo.

## Что не сделано

- **Автотест самого перетаскивания.** Всё вокруг Drag & Drop покрыто (правила, подбор, состояние, реакция интерфейса, клавиатурная навигация), но сам жест мышью в тестах не воспроизводится: в jsdom нет геометрии, а `@dnd-kit` считает попадание по прямоугольникам. Сценарии drop проверены вручную в браузере — перетаскивание секции в слот, перенос занятия, запрет невалидного drop с показом причины, возврат в зону нераспределённых. Планировалось закрыть это Playwright-тестом на реальной странице.
- **Мобильная раскладка.** Интерфейс тянется до планшета, ниже `lg` колонки складываются в одну, но отдельного сценария для телефона нет — там перетаскивание пальцем по сетке 5×6 требует другого решения, скорее выбор слота тапом.
- **Копирование занятия** ставит копию в первый свободный слот без конфликтов. Логичнее было бы дать перетащить копию с зажатым `Alt`, но это заметно усложняет обработку drop, поэтому оставлена кнопка в редакторе.
